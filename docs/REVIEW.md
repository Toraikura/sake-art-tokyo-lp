## 主従とページ内ゲーム

主はブランド/商品、ゲームは同じページで任意に触れる体験。ゲーム完了や登録を購入条件にしない。

画面順序：ブランド紹介 → 商品 → ページ内の酒母ゲーム → 飲み方・ブランドの話 → お知らせ → 漫画 → フッター。

QRからは `?bottle=sat-001&utm_source=label&utm_medium=qr` などで手元の一本を先に表示する。ゲームへのナビは `#playground` に変更し、別ページへ誘導しない。ゲーム後も同じページの該当商品へ戻れる。旧 `/play/` は互換用に残すが、主導線にはしない。

`assets/inline-play.js` は、年齢確認後かつ表示領域に近づいてから既存ゲームをiframeに読み込む。スタートボタンを自動で押す処理はない。同一オリジンでは `main > section#battle` を確認し、周囲のサイトヘッダーや他セクションをCSSで非表示にする。ReactのDOMツリーは削除・移動せず、温度操作と注意書きを残す。ResizeObserverでゲーム部分の高さに枠を合わせる。`data-app-ready` がtrueになる前は準備完了と表示しない。

これは暫定アダプターであり、ゲーム専用コンポーネントへの本統合ではない。ゲーム側の元ソースは確認できておらず、配布済みファイルを直接編集していない。DOM構成と同一ホスト名に依存し、隠した他機能のJSも読み込まれる。ゲーム更新やドメイン移行の前に元ソースから専用embedルートを作る。

別オリジンの単体HTMLプレビューではゲーム部分だけの分離ができず、枠内に遊び場全体が出る可能性を明示する。通信失敗・未準備時は再読み込みと単独表示への代替リンクを提示する。単独表示は通常導線ではなく障害時の補助。

## 購入と情報取得の未接続部分

前回ショップで確認した浦里オリジナルは1800mLで、旧LPの720ml・SAT商品との対応は未確認。同じ商品と決めつけず、現在は一般ショップの「販売状況を見る」に留める。容量・度数・価格・保管方法はラベルと販売ページを参照。正しい商品URL等の確認後、`assets/site-config.js` の `productUrls` を設定する。

登録・感想受付は未接続。`signupUrl` / `feedbackUrl` は未設定のまま。受付先・同意・配信停止・保存先を確認し、プライバシーを更新してから有効にする。最初は任意のメール登録を軸にし、感想送信と広告配信の同意を分ける提案。住所・電話・誕生日を入口で求めない。

`dataLayer` はメモリ内イベントだけで運営者への送信・集計はできない。ゲーム内の開始/終了も今回は新たに計測していない。ショップクリックは購入完了ではなく、売上追跡にはEC側との接続が必要。年齢確認と限定された流入元/商品IDの端末内保存は既存実装を維持。

## 検証と限界

JSのNode構文チェックを実行。Chromium 144.0.7559.96で今回39項目のローカルDOM検証を実施した。漫画の位置・非折りたたみ・縦横比、320/375/390/430/768/1440pxの横はみ出し、年齢確認前のゲーム未読込、同一ページの復帰、枠の高さ調整、周囲のみ非表示、操作部と注意書きの保持、準備状態・再読込・別オリジン時の警告を確認した。

ブラウザのURL遷移は `ERR_BLOCKED_BY_ADMINISTRATOR` で拒否されたため、HTML/CSSをメモリ内に注入し、URLクエリ・iframe通信・画像を検証用の代替にした。押したのはテスト用ボタンであり、実ゲームの動作検証ではない。実画像の見た目、iPhone実機/Safari、ネットワーク上のゲーム操作・購入・登録送信は未検証。

opaqueなsrcdocのsandboxを解除する補助テストでは同一オリジンに復帰できなかった。上記39項目にその復帰成功は含めない。実ネットワークの再試行・ホスト変更は未検証。前回の44項目を今回再実行したという意味でもない。
