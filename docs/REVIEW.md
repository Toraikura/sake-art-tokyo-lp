# SAT 改修案・レビュー事項

## 状態

2026-09-07の依頼に対するレビュー用実装。公開版は未変更。主従の最終承認と本番反映はYOSHIが判断する。

## 1. 見た目の変更

既存の紙色、トマト、バジルと既存画像を維持。背景グリッド、流れる文字帯、強い影、複数の予告ブロックを除去。商品一覧・詳細・ラベル一覧の重複を二つの商品カードに集約した。

漫画は商品紹介の後、飲み方のセクション内の折りたたみに移動。読みたい人だけ開き、さらに原画像を別画面で開ける。漫画画像自体は編集していない。

新作はSAT 003のComing soonのみ。SAT 004、地域・種別・発売時期を出す予告は撤回。現行READMEが商品情報未確定と明記していたため、容量・度数・価格を断定せずラベルと販売ページを参照させる。

## 2. 主従の提案

主：ブランドサイト。商品選択、購入先、商品ごとの情報、今後のお知らせ受付を担当。
従：Playground。任意で遊んで知る体験として位置づける。ゲーム終了や会員登録を購入の条件にしない。

QR → 手元の一本 → 味・飲み方 / 販売ページ
                       └ 任意でPlayground → 元の一本に戻る
                       └ 任意で感想 / 新作案内登録（接続後）

ブランド側に `/play/` を追加し、既存のゲームをiframeで表示する暫定案。上部には商品に戻るリンクと、埋め込みが使えない場合に元ページを開くリンクを常設した。

ゲーム側リポジトリにはgh-pagesと配布済みファイルしか確認できず、元のソースは見つかっていない。生成済みゲームを直接改変していないため、旧URLへの直アクセス時の「SHOP：準備中」はそのまま。完全な従属化は元ソースでブランドナビと購入リンクを共有する形に切り替える。iframeは長期の確定構成ではない。

## 3. 購入導線の未接続部分

既存ショップ `https://chillkaku.buyshop.jp/` は確認済み。公開一覧で確認できた浦里オリジナルは1800mLで、旧LPの720ml・SAT 001/002との同一性は未確認。誤った商品を「この一本」として接続しない。

現時点は「ショップで販売状況を見る」。正しい商品URL、容量、価格、配送・店頭受取の条件を確認した後、`assets/site-config.js` の `productUrls` を更新する。ヘッダー・フッターの一般ショップURLも同じ設定から反映される。

## 4. 情報取得の提案と現状

顧客情報と行動計測を分ける。

- 顧客情報：最初は新作案内のメール登録を軸とする案。任意の感想は商品ID・好み・飲み方程度に絞り、感想送信と広告配信への同意を分離する。住所・電話・誕生日は入口で求めない。
- 行動計測：QR入口、商品表示、ショップへの移動、Playgroundへの移動、商品への復帰を把握する。ショップクリックは購入完了ではなく、売上との対応にはEC側の計測・注文データとの連携が必要。

現在は登録先・感想受付先とも未設定。フォームは出さず、Instagramへの実在リンクを案内する。`signupUrl` / `feedbackUrl` に検証済みのHTTPS URLを設定して初めて導線を表示する。外部サービス側の項目、同意、解除、保存先、動作を確認し、プライバシーの表示を更新してから有効にする。フロントの設定だけで受付完了とみなさない。

`dataLayer` はブラウザのメモリ内だけ。解析タグも送信先も未接続であり、運営者はまだ集計できない。氏名・メール・自由文・生のURLをイベントに含めない。QR流入元と商品IDは限定値のみをタブ内に保存し、ゲーム往復で維持する。ゲームからの復帰をQR入口として重複計上しない。リロードを含めたユニーク集計は解析側で設計する。

## 5. 確認できたこと / 未確認

確認済み：旧LPのHTML・CSS・JS、README、プライバシーページの全文と画像ファイル名。Playgroundは公開内容とリポジトリの配布構成。今回のJSはNode構文チェックを通過。

ローカル検証：Chromium 144.0.7559.96にHTML/CSSを注入し、実DOMのクリック・dialog・折りたたみ・レイアウトをテスト。URLとlocalStorage/sessionStorageはテスト用の代替。44項目通過。320 / 375 / 390 / 430 / 768 / 1440pxで横はみ出しなし。390×844のQR表示ではショップボタンが初期画面内に入ることを確認（画像未読込条件）。

未確認：公開画像そのもの、実ネットワーク上の画面遷移、iframe内のゲーム動作・ダウンロード、iPhone実機・Safari/WebKit、既存ラベルのQR実値、商品別購入完了、メール登録・感想の送信。公開ページへのブラウザ接続とローカルURL遷移が環境側で制限されているため、実機検証済みとはしない。

## 6. 公開前の順序

1. YOSHIが画面案と「ブランド主 / Playground従」を承認する。
2. 印刷済みQRの読み取り先を確認し、既存URLを壊さず商品別URLに接続する。今後のラベルは所有ドメインの恒久的な入口を推奨し、未確定URLのまま印刷しない。
3. 商品別販売URLと登録・感想受付先を確定する。配信や保存についての案内を更新する。
4. 元のPlaygroundソースでブランドへの復帰と商品リンクを実装する。暫定iframeのまま公開する場合も、iPhoneのタッチ、スクロール、PNG保存、外部リンク、戻る操作を検証する。
5. 公開プレビューで画像・導線・年齢確認を確認し、mainへマージする。今回の作業ではマージ・公開はしない。
